## 0. The one rule
A single fixed typed read-only lookup that returns a minimized, projected field set. NOT a generic query API. No caller-chosen path/method/filter/raw-query/field-selection, no batch/export, no writes. Drift voids Cipher's container waiver → dedicated-VM. Keep this exact shape.

## 1. Deploy target (recon-confirmed)
**PROD on xerox** (`app.programaincluir.org`, DB `incluir_hono`, ~1042 students). The Mini's `incluir-hono-postgres:54321` is DEV (23 students) — **do not use.** Mount the Hono route into `apps/hono-app/src/http/app.ts` (~:1110).

**Frontend proxy composition surface (recon: `app.programaincluir.org` routes to the FRONTEND; there is NO `/api/bot` proxy today).** The E2E path is Traefik → frontend → Hono, so a new Next route is REQUIRED: **`apps/frontend/src/app/api/bot/students/by-name/route.ts`, POST only** (no generic `bot` catch-all). It MUST:
- **Verify the INGRESS HMAC BEFORE forwarding anything to Hono [blocker 4].** The proxy MUST **bounded-buffer the ≤1 KiB raw body**, then strictly validate the three ingress headers (`X-Hermes-Ingress-Timestamp` = decimal digits, `X-Hermes-Ingress-Nonce` = exactly 32 lowercase hex, `X-Hermes-Ingress-Signature` = exactly 64 lowercase hex) + timestamp window (±60s) + a **CONSTANT-TIME ingress-HMAC check** over the §2.0 ingress canonical (env `HERMES_BOT_INGRESS_SECRET`). If the ingress HMAC is **missing / invalid / expired → TERMINATE at Next with a 4xx, making ZERO Hono calls.** On a VALID ingress HMAC → **STRIP the three `X-Hermes-Ingress-*` headers** and forward the rest. Env unset → 503 fail-closed. (This ingress HMAC — not a pre-auth rate bucket — is what makes "a public invalid flood cannot block a valid broker call" representable: an attacker without `HERMES_BOT_INGRESS_SECRET` never reaches Hono at all.)
- **Consume the INGRESS nonce authoritatively at Next [blocker 2 — the ingress nonce was signed but never checked].** AFTER a VALID ingress HMAC and BEFORE any Hono call, perform an atomic **`SET bot:ingress-nonce:<X-Hermes-Ingress-Nonce> 1 NX EX 180`** in the authoritative Next-tier store (the same Redis, env-guarded). Key already present → **duplicate ingress nonce (replay) → TERMINATE at Next with a 4xx, ZERO additional Hono calls.** **Nonce-TTL invariant [v3.5 blocker]: the nonce cache entry MUST outlive the full timestamp validity span. The timestamp window is inclusive ±60s = a 120s total validity span, so the TTL is set STRICTLY GREATER at `EX 180` — nonce TTL > (max timestamp skew window) so no in-window replay can outlive its nonce entry** (a `EX 120` TTL equal to the span would let a request replayed at the boundary, after the nonce entry expired but while its timestamp is still in-window, slip through). Fail-closed: if the ingress-nonce store is unavailable → 503, never fail-open; the memory fallback is dev/test ONLY and unreachable in prod. This is a SEPARATE nonce namespace from the §2.2 service nonce (distinct key prefix), consumed at a distinct tier.
- **Reject ANY non-empty URL query string at Next [blocker 5].** A request whose URL carries a non-empty query (`/api/bot/students/by-name?…`) is rejected before any Hono call — names in a URL must be impossible. Hono independently re-rejects a non-empty query (§3). Neither tier binds the query into the signed canonical, so it must be empty at both.
- **Forward the SAME verified byte buffer to Hono — ONE representable body mechanism [blocker 4].** The contract is exactly: **bounded-buffer the raw ≤1 KiB bytes → verify the ingress HMAC over THAT buffer → forward that SAME verified byte buffer.** There is NO live-stream alternative — after buffering, the `req.body` / `duplex: 'half'` live-stream path is **REMOVED**. Forward with no parse, no re-serialize, no BOM/whitespace mutation, so the forwarded bytes are **byte-identical to the verified bytes** and BOTH the §2.0 ingress body hash and the §2.1 service body hash match.
- Forward `Content-Type`, plus the **four SERVICE `X-Hermes-*` headers UNTOUCHED** (`Aud` / `Timestamp` / `Nonce` / `Signature` — Next never verifies or mutates the service signature, only Hono does). Forward **NO Cookie, NO Authorization**, and **NO `X-Hermes-Ingress-*`** (stripped above).
- **Cap the READ into the bounded buffer at 1 KiB even if `Content-Length` is absent or false** — enforce the byte cap on the bytes actually read into the buffer, not by trusting the header. This is a cap on the buffered read, NOT stream passthrough: the route buffers-then-forwards, it does not forward live.
- **Content-Length integrity [blocker 7]:** the proxy MUST NOT blindly forward the caller's declared `Content-Length`. It has already bounded-buffered the (≤1 KiB) body, so it **rejects a declared-vs-actual length mismatch;** then either **recomputes the outbound `Content-Length` from the buffered byte count**, or **omits `Content-Length` entirely** (chunked). **NEVER forward an untrusted/incorrect length** — a caller-declared length that disagrees with the buffered byte count would either truncate the signed body at Hono (hash mismatch) or smuggle a second request.
- Return `Cache-Control: no-store`.
- Add **BOTH** this proxy AND the Hono route to the telemetry/body-capture skip-list (§5) — a **non-removable built-in union**, not an env-replaceable list.
- This proxy is a **production runtime contract** and MUST be disclosed in the PR body.

## 2. Auth — TWO domain-separated per-request HMACs (NOT a static bearer) [Cipher blockers 1, 2, 4]
No durable bearer token. The broker **signs every request TWICE** — an INGRESS envelope verified constant-time at the Next proxy, and the existing SERVICE envelope verified at Hono. The server verifies before any DB work. **Domain separation is strict: distinct secrets, distinct aud constants, distinct header names; a key from one layer is NEVER accepted in the other, and neither key is ever reused.**

- **SERVICE secret:** `HERMES_BOT_SIGNING_SECRET` — high-entropy, rotatable, held ONLY by broker + xerox/Hono server (Peppy sets it on the xerox env; Infisical-sourced). **Env unset → 503 fail-closed.**
- **INGRESS secret:** `HERMES_BOT_INGRESS_SECRET` — high-entropy, rotatable, held ONLY by broker + the Next proxy. **Env unset → 503 fail-closed.** Distinct from the service secret; never reused.
- **SERVICE headers (broker → Next → Hono, forwarded UNTOUCHED by Next):** `X-Hermes-Aud: incluir-bot`, `X-Hermes-Timestamp` (unix seconds), `X-Hermes-Nonce` (128-bit random hex), `X-Hermes-Signature` (hex HMAC-SHA256).
- **INGRESS headers (broker → Next ONLY, STRIPPED by Next before forwarding):** `X-Hermes-Ingress-Timestamp` (unix seconds), `X-Hermes-Ingress-Nonce` (128-bit random hex), `X-Hermes-Ingress-Signature` (hex HMAC-SHA256).
- **Noted stronger alternative (NOT the chosen design):** mTLS on a **DEDICATED bot hostname** is a valid stronger option than the ingress HMAC; but do **NOT** bolt client-auth onto the shared app hostname. Recorded as an alternative only — the chosen design is the two-HMAC contract above.

### 2.0 INGRESS canonical [blocker 4] — verified at the Next proxy, never at Hono
The broker signs an INGRESS ENVELOPE over its own domain-separated canonical string, using `HERMES_BOT_INGRESS_SECRET` and a **DISTINCT aud constant** so an ingress signature can never be replayed as a service signature (and vice-versa):
```
ingress_canonical =  "incluir-bot-ingress"                (literal DISTINCT ingress aud constant)
                  \n "POST"                               (literal uppercase method constant)
                  \n "/api/bot/students/by-name"          (literal route constant — no query, no host, no trailing slash)
                  \n <X-Hermes-Ingress-Timestamp>          (decimal ASCII digits only)
                  \n <X-Hermes-Ingress-Nonce>              (exactly 32 lowercase hex chars = 128 bit)
                  \n sha256hex(<exact raw ≤1KiB body bytes>) (lowercase hex; the bytes as received, pre-parse)
```
The Next proxy verifies this constant-time (§1) before making ANY Hono call, then **atomically consumes the ingress nonce (`SET … NX EX 180`, blocker 2 — TTL strictly greater than the 120s ±60s validity span, §1 nonce-TTL invariant)** so a replayed ingress envelope is rejected at Next with zero additional Hono calls. The ingress envelope is consumed and stripped at Next; Hono never sees or verifies it.

### 2.1 UNAMBIGUOUS canonical input [blocker 2]
The signed byte-string is fully specified so broker and server derive identical bytes with zero interpretation latitude:
```
canonical =  "incluir-bot"                       (literal aud constant)
          \n "POST"                              (literal uppercase method constant)
          \n "/api/bot/students/by-name"         (literal route constant — no query, no host, no trailing slash)
          \n <X-Hermes-Timestamp>                (decimal ASCII digits only)
          \n <X-Hermes-Nonce>                     (exactly 32 lowercase hex chars = 128 bit)
          \n sha256hex(<exact raw request-body bytes>)   (lowercase hex; the bytes as received, pre-parse)
```
- **Header syntax is strict and validated BEFORE anything else:** `Content-Type: application/json`; body length ≤ **1 KiB** (reject larger before reading); `X-Hermes-Timestamp` = decimal digits only; `X-Hermes-Nonce` = exactly 32 lowercase hex; `X-Hermes-Signature` = exactly 64 lowercase hex. **Reject duplicate or malformed signature/content headers BEFORE body parse.** Any syntax miss → 400/401 with zero DB work.
- The body hash is over the **exact raw bytes** as received (no re-serialization, no canonical JSON) so the frontend proxy must preserve them verbatim (§8, blocker 5).

### 2.2 Verification ORDER at Hono (strict, fail-closed) [blockers 1, 4]
By the time a request reaches Hono, the Next proxy has ALREADY verified + stripped the ingress HMAC (§1, §2.0) — a public attacker without `HERMES_BOT_INGRESS_SECRET` never gets here at all. **The pre-HMAC shared-proxy 10/min pre-auth bucket is REMOVED entirely** (it was the impossible-lockout bug). Enforce in this exact sequence; the SERVICE HMAC is verified FIRST, so only INVALID service signatures can touch the invalid-only bucket, the service nonce is consumed on a valid signature, and — critically [blocker 1] — the **valid-request bucket is debited LAST, AFTER the nonce SET NX succeeds**, so a captured valid request replayed cannot exhaust the legitimate 10/min+100/day quota:
1. **Traefik/proxy pre-parse ceilings** (§5, §6) — STRUCTURAL header/body/read/concurrency limits enforced before parse (§6, blocker 3).
2. **Strict header syntax + bounded body** (§2.1) — reject malformed/duplicate headers, wrong content-type, oversize body. Reject any non-empty URL query (blocker 5).
3. **`aud === "incluir-bot"` AND `|now - timestamp| ≤ 60s`.**
4. **Verify the SERVICE HMAC FIRST (constant-time)** — recompute over §2.1 canonical, `timingSafeEqual`. This gates everything below.
5. **INVALID service signatures ONLY** consume the **invalid-only bucket** (§6) — a separate counter that fails closed in prod (Redis outage → 503). **Its saturation MUST NOT reject a valid request.**
6. **ONLY after a valid service signature — atomic service nonce FIRST [blocker 1]:** **`SET bot:nonce:<nonce> 1 NX EX 180`** on Redis. **Key already present → replay → reject, leaving the valid-request counters UNCHANGED** (the debit in step 7 has not run yet). This runs BEFORE the valid-bucket debit so a captured valid request cannot replay and drain the legitimate quota, and so an attacker cannot burn nonces with unsigned/invalid traffic. **Nonce-TTL invariant [v3.5 blocker]: `EX 180` is set STRICTLY GREATER than the ±60s = 120s timestamp validity span — nonce TTL > (max timestamp skew window) — so a request replayed at the boundary (after a `EX 120` entry would have expired but while its timestamp is still in-window) cannot outlive its nonce entry and slip through.**
7. **THEN debit the INDEPENDENT valid-request bucket** (§6, 10/min + 100/day) — consumed ONLY by a fresh (non-replayed) valid request, never touched or exhausted by invalid or replayed traffic.
- **Redis is authoritative for the nonce cache in prod. A production Redis outage → 503 fail-closed.** The in-memory nonce fallback is **dev/test ONLY** and MUST NOT be reachable in prod (guard on env). Wrong-route/expired/replayed/invalid-sig/malformed → reject **before any query**, audited in middleware (§5).
- Token/secret maps to NOTHING in the user/role graph — not a BetterAuth credential, no session, cannot be used as browser/admin/session auth, no `role==='admin'` bypass. It only unlocks `/api/bot/*`.
- **Do NOT** add a BetterAuth apiKey/bearer/jwt plugin; **do NOT** reuse a human session cookie. (If, and only if, operator explicitly accepts the risk, a static-secret bearer is the fallback — but default is HMAC; a static bearer must be flagged to GLaDOS/operator as a waiver deviation. Going with HMAC.)

## 3. Operation — ONE typed lookup, **POST** (names never in a URL) [blockers 2, 4, 6]

### `POST /api/bot/students/by-name`
- **Method POST**, JSON body — because raw student names must NOT appear in a query string (URLs leak into proxy logs, OTel attrs, Sentry, caches, access logs). Method is not the read-only control; the token scope + server code are (§2, GET-only queries).
- **Reject ANY non-empty URL query string at Hono [blocker 5]** (independently of Next's §1 rejection): a request to `/api/bot/students/by-name?…` with a non-empty query is rejected with zero DB work. The query is NOT part of the signed §2.1 canonical, so it must be empty — names in a URL are impossible at both tiers.
- Body: `{ "name": string }` — required, 2–80 chars, letters/spaces/`.-'`+accents only (reject else). Trim + Unicode-normalize (case/accent-insensitive) server-side.
- **Match:** **exact only** via a **parameterized** predicate on the **singular `user` table** — `WHERE unaccent(lower(user.name)) = unaccent(lower($1))`, using the **EXISTING `unaccent` extension** (no new extension needed). **No prefix, wildcard, ILIKE-%, or regex.** There is **NO normalized/indexed/computed name column** — do not claim one. A **bounded DB-side scan over ~1042 rows** inside the 2s read-only transaction (§7) is **explicitly acceptable**; no new index or migration is required unless Rex adds a separately-reviewed one.
- **Soft-delete filtering [blocker 3 — the query must NOT resurrect deleted PII]:** every join filters `deleted_at IS NULL` on ALL of `students.deleted_at`, `user.deleted_at`, `classes.deleted_at`, `courses.deleted_at`, `semesters.deleted_at` (all nullable `timestamptz`). Record VALIDITY = `students.deleted_at IS NULL` — the legacy `students.is_active` flag is **DROPPED, not used or exposed**. `courses.is_active` = catalog visibility only (**NOT** participation). The class→semester join is by the **year+semester tuple** (`classes.year/semester ⋈ semesters.year/semester`) — the ADR's `classes.semester_id` wording is STALE; **do not use `semester_id`**.
- **Bound + dedup ORDER [blocker 4]:** the predicate matches enrollment rows, but the result is **distinct PEOPLE**. Apply in this order: (1) select matching **soft-delete-filtered** enrollment rows (all joins `deleted_at IS NULL`); (2) **pick ONE enrollment per person deterministically** = partition/dedup by `user_id`, ordered `ORDER BY classes.year DESC, classes.semester DESC, students.created_at DESC, students.id DESC` (`classes.year`/`classes.semester` joined by tuple to `semesters.year`/`semesters.semester`; `students` supplies `created_at` and `id` for the stable tiebreak) — a numeric/date comparison, **never** a label/string comparison; (3) **THEN `LIMIT 6`** applied AFTER person dedup **and** after the soft-delete filters. Return ≤5 results. If a 6th person exists → `{ "tooMany": true }` with **NO count** (exact counts aid enumeration). If 0 → `{ "results": [] }`.
- Response: `{ "results": StudentSummary[] }` (≤5). **No student/enrollment IDs cross to the model** — resolves the id-inconsistency; the operator disambiguates by reading the (≤5) summaries. (No `by-id` op in v1; if drill-in is later needed, add a broker-local ephemeral handle + fresh Cipher review.)
- Headers on every `/api/bot/*` response: `Cache-Control: no-store`.
- **Returns:** distinct PEOPLE (students), each with the summary of their **most-recent enrollment** as defined deterministically above. (by-name returns people, not raw enrollment rows — the person↔enrollment mapping keys on `user_id`, and the "latest" ordering uses the numeric `classes.year`/`classes.semester` → `semesters.year`/`semesters.semester` columns with `students.created_at`/`students.id` as tiebreak, NOT a label string.)

## 4. `StudentSummary` — exact projected field allowlist [blocker 3 + Rex VERIFIED schema]
Literally these fields, nothing else (enumerate the output object; never spread a row). **This set MUST match Lane 2 §5 broker re-projection exactly:**
```
studentName        : string     // user.name — the person's name (disambiguator; PII crossing to OpenAI/Slack)
activeThisSemester : boolean     // DERIVED (see below): a live student row ⋈ live active class ⋈ live active semester
academicOutcome    : "pending" | "approved" | "rejected"   // from students.status (academic outcome ONLY) — INCLUDED (operator accepted, see below)
enrollmentSemester : string      // from THIS enrollment's class year+semester — NEVER an active-semester fallback
className          : string | null
courseName         : string | null
attendanceSummary  : { presencasLetivas: number, totalDiasLetivos: number } | null   // AGGREGATE-only, bound to enrollmentSemester; NO dates, NO current-active fallback
```
- **`activeThisSemester` (boolean) is DERIVED** — true iff a live student row joins to a live active class joined to a live active semester:
  `students.user_id = user.id` · `students.deleted_at IS NULL` · `classes.id = students.class_id` · `classes.deleted_at IS NULL` · `classes.is_active = true` · `semesters.year = classes.year AND semesters.semester = classes.semester` · `semesters.deleted_at IS NULL` · `semesters.is_active = true`. (This REPLACES the old `enrollmentActive`/`students.is_active` field — `students.is_active` is a legacy inconsistent flag, DROPPED entirely.)
- **`academicOutcome` (students.status pending/approved/rejected) is INCLUDED** — the operator **explicitly accepted it crossing OpenAI + Slack (GLaDOS-confirmed 2026-07-30)**, satisfying Cipher's data-boundary condition. **Grades remain OUT regardless.**
**DEFAULT-DENY (must NOT appear):** any student/user/enrollment/class/course/semester ID, cpf, dob, phone, email, address, guardians, health/support notes, documents, financial data, **grades**, free-text notes, all internal/auth fields, and the legacy **`students.is_active`** flag.

## 5. Audit + telemetry hygiene [blocker 2, 5]
- **Audit in MIDDLEWARE** (route-only logging cannot see auth failures): every request (incl denied) logs `service="hermes-bot"`, op, outcome (ok/too-many/empty/denied-sig/denied-rate/denied-replay), result-count, timestamp. **NEVER** raw name, body, token, secret, or nonce value.
- **Bounded, metadata-ONLY Next denial audit [blocker 6 — reconcile zero-Hono ingress denials with the every-request audit claim].** Ingress denials (bad/missing/expired/replayed ingress HMAC or nonce) TERMINATE at Next and NEVER reach Hono, so Hono's middleware audit structurally cannot see them. The Next proxy therefore MUST emit its OWN denial audit: a **bounded metadata-only counter** with outcome ONLY (`ingress-denied-sig` / `ingress-denied-expired` / `ingress-denied-replay` / `ingress-denied-query` / `ingress-denied-malformed`) + timestamp. It **NEVER logs body, name, signature, nonce, or query value**, and it is **rate-bounded / aggregated (a counter, not a per-request line)** so a public flood cannot amplify logs. A test proves the Next denial counter increments on ingress denial, carries no PII/secret/nonce, and does not amplify (§8).
- **Exclude `/api/bot/*` from all body-capture + URL/query telemetry** as a **NON-REMOVABLE built-in UNION in code [blocker 5]** — `/api/bot` (and `/api/auth`) are hard-coded into the effective skip-set and UNIONed with any operator list; they are **NOT env-replaceable**. The current `TRACE_BODIES_PATH_SKIP_LIST` env-replacement is a hole: an env value that omits `/api/bot` would silently re-enable body/name capture. The built-in union closes it. Confirm no name/body/query/token reaches OTel attributes, Sentry, access logs, or any cache.
- **Both telemetry layers on the composition path** (the frontend/edge proxy AND Hono) MUST omit body, `name`, and the signature headers from their logs/traces — the raw name must not surface at the proxy tier either (§8, blocker 5).
- Operator identity is audited **separately, broker-side**, from the authenticated Slack event — never a request arg to this API. This endpoint knows only the bot service identity.

## 6. Rate limits — Redis-backed, deploy-persistent, INDEPENDENT buckets [blockers 4, 5]
**There is NO pre-HMAC shared-proxy bucket** — that design (v3.2) created the impossible lockout and is REMOVED. The two Hono buckets below are gated by service-HMAC validity (§2.2), so an invalid flood can never touch the valid budget.
- **Invalid-only bucket [blocker 4]** — consumed **ONLY by requests whose SERVICE HMAC already FAILED** (§2.2 step 5). Keyed on the authenticated signing identity is impossible for invalids (they have none), so it is a coarse anti-abuse counter, **fails closed in prod** (Redis outage → 503). **Its saturation MUST NOT reject a valid ingress+service-HMAC request** — validity is proven before this bucket is ever consulted.
- **Valid-request bucket**, keyed on the **authenticated signing identity**: **10 valid lookups/min + 100/day**, **single concurrent lookup** — consumed ONLY by requests with a VALID service HMAC. (Cipher's proposed ceiling; Rex had suggested 20/min — using Cipher's 10 as the reviewed number, Rex/Cipher may adjust. Broker enforces equal-or-stricter.)
- **The two buckets are INDEPENDENT [blocker 4]:** because the SERVICE HMAC is verified FIRST, an invalid-signature flood consumes only the invalid-only bucket and can NEVER consume, throttle, or lock the valid-request bucket; and a public attacker without `HERMES_BOT_INGRESS_SECRET` is terminated at Next and reaches neither bucket. A test MUST prove public invalids cannot exhaust/lock the valid budget (§8).
- **Traefik/proxy enforce STRUCTURAL ceilings ONLY [blocker 3].** Traefik/the proxy MAY enforce **STRUCTURAL body/header/read/concurrency ceilings** (pre-parse resource limits) and NOTHING else — they run no rejecting *rate* bucket against a signature. **Any ingress-invalid *rejecting bucket* MUST run at Next, AFTER an ingress-HMAC FAILURE, and MUST NEVER gate a valid ingress signature.** If it tracks invalids at all, it keys on a **TRUSTED PEER address — NEVER caller-supplied `XFF`/`X-Forwarded-For`** — and its saturation must **never reject a valid ingress-HMAC request**.
- **Volumetric resource exhaustion is a SEPARATELY-STATED RESIDUAL [blocker 3]:** the structural ceilings above bound per-request cost, but raw volumetric flooding (L3/L4 or valid-ingress-HMAC-less L7 volume that Next 4xx-terminates) consuming network/CPU/connection capacity is an **accepted residual, NOT something a bounded functional test can prove impossible.** The tests prove a public flood cannot *lock the valid budget* (§8), not that it cannot consume infrastructure capacity — those are different claims and this one is documented as residual, not closed.
- Backed by the **existing Redis adapter on xerox** so counters **survive restart/deploy**. **Fail-closed in prod:** a Redis outage → the invalid-only limiter (and nonce cache, §2.2) return **503**, never fail-open. The **memory fallback is dev/test ONLY** and must be unreachable in prod (env-guarded).

## 7. Hard timeouts + read-only transaction [blockers 3, 7]
- **Run the lookup inside a DB READ-ONLY transaction** so "no writes" is structural, not just a code convention: `BEGIN; SET TRANSACTION READ ONLY; SET LOCAL statement_timeout = 2000; <parameterized SELECT>; COMMIT;`. `SET LOCAL` binds the timeout to **this same connection/transaction** (not a session global that could leak or be reset), giving real **cancellation** at 2s — not merely abandoning the promise. A write attempt inside the txn errors by construction.
- **Single-concurrency lease** (mirrors §6 single-concurrent-lookup): acquire with a **TTL** so a crashed/timed-out request cannot wedge the lane, and **release in a `finally`** so the normal path always frees it. TTL > statement_timeout so it can never expire mid-query.
- Broker 3s. Total Slack tool-call budget 5s.

### 7.2 HMAC secret rotation — BOUNDED-DOWNTIME, single mechanism, BOTH keys [blocker 6]
Mirrors Lane 2 §5 (both lanes carry the same drill). Now covers **BOTH** `HERMES_BOT_INGRESS_SECRET` and `HERMES_BOT_SIGNING_SECRET`. **NO dual-key, NO key-id header, NO overlap branch:** (1) **stop** the tool path; (2) update **both** secrets on **both holders** — the ingress secret on the **Next proxy** + broker, the signing secret on **xerox/Hono** + broker; (3) **start**; (4) **prove BOTH verifiers rotated INDEPENDENTLY [blocker 7] with these THREE tests (replacing the single "old signature rejected" test).** **Signature-mismatch isolation [v3.5 blocker]: each mixed-key probe MUST be FRESHLY SIGNED with an IN-WINDOW timestamp and a FRESH UNUSED nonce, and the test MUST ASSERT the rejection tier + reason is SPECIFICALLY signature mismatch — never expiry, never replay. A probe rejected for expiry or replay is a FALSE PASS (a stale/old key could still be accepted while the test passes for the wrong reason) and does NOT satisfy this drill.** The three probes: (i) **old-ingress + new-service → rejected AT NEXT for INGRESS SIGNATURE MISMATCH** (freshly signed, in-window, fresh nonce; the Next ingress verifier now holds only the new ingress secret, so the stale ingress envelope fails the constant-time ingress-HMAC check before any Hono call — not for expiry/replay); (ii) **new-ingress + old-service → rejected AT HONO for SERVICE SIGNATURE MISMATCH** (freshly signed, in-window, fresh nonce; the ingress check passes at Next and consumes the fresh ingress nonce, but Hono's service verifier now holds only the new signing secret, so the stale service envelope fails the service-HMAC check at Hono — not for expiry/replay); (iii) **new-ingress + new-service → accepted.** No dual-key/overlap for either secret.
